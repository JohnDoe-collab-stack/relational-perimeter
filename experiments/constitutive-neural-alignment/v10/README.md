# Constitutive neural capability comparison v10

This version supersedes the unexecuted v9 comparison protocol because v9's
compiled command emitted only the six class adapters although its text also
required a relational comparator, an explicit reference combination and an
independent complete recheck.  No v9 file or reserved result is changed.

The v10 command emits exactly nine immutable NDJSON rows.  All methods consume
the same frozen learned artifact lineage, while each receives the additional
current-domain, intervention, future, contract, version or serialized-update
material that its interface can use.  `translation-ledger.json` records these
conversions; a count is bookkeeping, not a capability score or runtime cost.

`capability-matrix.json` freezes the P1--P7 decision cells.  Proof-backed cells
name exact Lean declarations.  Cells beyond an interface are reported as
`out-of-interface`; missing certification remains `not-certified` and is never
converted into an impossibility claim.  `authorized-ablations.json` fixes the
negative fixtures used for P7.  `success-criteria.json` records S1--S5 and
S7--S8 honestly before the run; in particular literature fidelity and the
final independent scientific audits remain open.

`method-correspondence.json` records the exact local property, domain,
arithmetic, version and trust boundary used by each row.  The first six rows
are repository-local typed adapters for named research classes.  They are not
asserted to be extensionally complete implementations of every external
method in those classes.  Consequently semantic equivalence with the external
classes and residual scientific novelty remain open even when a local cell is
proof-backed.

`COMPARATIVE_SCOPE.md` answers the five interpretation questions fixed by the
project before the run.  It records the successes of the local reference rows
and states that no residual scientific gain is yet certified.

The confirmatory runner refuses a dirty worktree, an unstable commit, changed
inputs, partial output or a pre-existing result.  It never overwrites a result.
The protocol must therefore be committed before its single confirmatory run.
